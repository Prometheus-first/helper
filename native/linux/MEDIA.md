# Linux 通用媒体接收与表情导出

适配官方 Linux 微信 4.1.13.26 x86_64；精确 ELF 指纹、账号、进程与连接检查继续适用。

## 普通插件的媒体事件

管理台后端开放 `image.receive`、`file.receive`、`voice.receive`，以及对应的
`friend.*.receive` / `group.*.receive`。插件仍须在 manifest 的 `message_types`
包含 3、49、34 等需要处理的类型。

只有本连接成功校验并保存的完整媒体才投递到普通插件，每条原生消息仅一次：

| 类型 | 路径 | 其他字段 |
| --- | --- | --- |
| 图片 3 | `message.image_path` | `data['image_status'] == 'ready'` |
| 文件 49，附件 6/74 | `message.file_path` | `file_status`、`file_name`、`file_size` |
| 语音 34 | `message.data['voice_path']` | `voice_status`、`voice_duration_ms`、`voice_size` |

pending、failed、unavailable 仍用于消息监控及防撤回状态关联，不交给普通插件。
自发消息与机器人发送回声不触发普通媒体玩法。缓存仍受白名单、账号、连接、
大小/数量预算和无链接私有路径限制；ready 时重新核对缓存文件身份。
停止或换连接后清理接收缓存，插件不应长期保存旧路径。

图片与文件缓存使用有限并发，避免单条媒体长时间等待时阻塞后续消息；
先收到撤回通知也会继续等待原消息的缓存结果。群图片沿用受白名单与连接
代次约束的自动下载。收发白名单为空时，自动下载范围覆盖当前账号的普通
好友与群会话；配置白名单时只覆盖其中允许的会话。文件只处理已完整落盘并通过大小及 MD5 核对的附件，
尚未新增未落盘文件主动下载。媒体在下载完成前被撤回时，可能仍无法恢复。

微信可能把同一张高清图片缓存硬链接到当前账号的两个会话目录。接收器仅在两个
`msg/attach/<会话摘要>/<年月>/Img/<图片摘要>_h.dat` 路径都属于当前账号、均指向
同一个仅有两条链接的文件，且读取前后文件身份不变时接受此布局。内容仍须通过
消息长度与 MD5 核验；这不证明文件一定与发送方原始文件逐字节一致。
语音沿用完整 SILK
接收和精确群/消息编号的只读语音数据库补充，最多 60 秒、256 KiB，不含 ASR。

普通插件与防撤回共享完整缓存，已有撤回去重与连接取消规则保持适用。

## 本地表情缓存导出

网页“群聊与会话”提供“导出本地表情”，可选择生成 GIF 预览。
插件声明 `emoticon.extract` 后可调用 `ctx.export_emoticons(convert=True)`；
返回现有 `ExportedEmoticon` 元组，路径指向 Linux 本机的私有导出目录。
源文件不改动，不自动发送表情，不把本地缓存称为完整收藏列表。

当前仅遍历已确认的 `business/emoticon/Persist/<hex2>/<hex32>` 与
`Thumb/<hex2>/<hex32>.thumb` 及共享导出器支持的直接文件布局，
其他分类不递归。沿用共享 PNG/GIF/WXGF 校验、原件保存、GIF 转换与失败码。
WXGF 的 GIF 为 30 fps 预览，不保证原始播放时间完全一致。
限额为 256 个缓存文件、单文件 20 MiB、合计 100 MiB；GIF 转换另受帧数、
像素、尺寸、输出大小及超时限制，转换失败仍保留成功导出的原件。

表情缓存密钥与图片密钥不同。模块相对 VA `0x61a00e0` getter 读取
账号服务 `hub+0x240` 的 libc++ string；`0x61a014d..0x61a0183`
是编译后的固定 XOR 掩码，producer 位于 `0x619a6f0..0x619a869`。
已验证 16 字节字段及 short/long string 读取；只在内存中取得本账号 AES-128
材料，使用 CBC、相同 key/IV 和严格 PKCS#7 校验。它不是图片 `hub+0x228`
字段，也不对密钥做十六进制二次解码。密钥不写日志、配置或导出文件。

网页导出是独立后台任务，核对账号、连接及能力，限制同时运行一项。
停止、重启、切号或断线后隐藏旧结果；操作不会开放任意本地文件下载接口。
导出结果显示 Linux 本机路径和条目统计，可用于已有本地文件发送流程。

## 实机与离线验证

当前账号缓存中的一组 WXGF 原件与 PNG 缩略图已完整导出；WXGF 解码后
生成 192×192、47 帧 GIF，帧数保留，重新读取验证可发送。
这只证明本机已有缓存集合，不代表收藏列表完整。

群实测通过普通插件收到一张完整图片、两条不同原生编号的文件消息及一段短语音；
四条消息各处理一次，没有重复投递，图片解码、文件字节读取和 SILK 时长检查通过。
该测试停用自动回复，只记录接收结果。私聊媒体使用同一链路并有离线闭环覆盖，
本轮没有另做私聊实机接收。
