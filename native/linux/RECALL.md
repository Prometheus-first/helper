# Linux 防撤回：实现与验证边界

目标版本为官方 Linux 微信 4.1.13.26 x86_64。沿用 ELF SHA-256、Build ID、入口字节、当前登录账号和本地通道 PID/UID 检查。这里记录的是该版本上的实现和证据，不能推广到其他版本。

## 当前结果

| 类型 | 实现 | 本轮验证 |
| --- | --- | --- |
| 文字、内置表情、emoji | 现有 `anti_recall` 按原消息编号缓存与补发；每条最多 2000 字符 | 实机文字撤回恢复成功一次；不代表任意长文字完整恢复 |
| 动态表情 type 47 | 复用原件下载与 GIF 校验，调用 Linux 原生表情发送 | 实机撤回恢复成功，接收端确认能够播放 |
| 图片 type 3 | 精确白名单原生下载、当前账号缓存读取、V2 解密和完整 MD5 校验 | 未点开 Linux 端图片时后台下载与群撤回补发实机通过，接收端确认可正常打开 |
| 普通附件 type 6/74 | 读取微信已落盘且名称、长度、MD5 匹配的文件，快照后按原文件名补发 | 重名缓存识别、群撤回后单次 type 49 补发实机通过，接收端确认收到并能下载打开 |
| 语音 type 34 | 已接入专用私有缓存与原生语音条发送；完整音频由当前账号语音数据库补充读取 | 1 秒测试音可播放；新群短语音自动缓存、撤回后单次 type 34 补发及接收端原声播放均实机通过 |

独立好友图片下载、附件回发工具以前的实机成功，只证明对应工具路径，不替代管理台防撤回闭环。监控显示“已撤回”也不代表原件已经缓存或补发成功。

## 消息与缓存链路

1. `linux_panel_backend.py` 将收到的媒体 XML 解析为类型受限的元数据；图片或附件凭据不会进入公开消息字段。撤回通知使用共享解析器提取原消息编号，普通消息和撤回均保留同一个编号。
2. `SessionLease` 核对原生连接标识，再绑定本轮机器人的 `session_id`。每个 lease 拥有自己的接收器和 emitter；账号变化、停止或重启后的旧回调不会被改写为新连接消息。
3. `LinuxMediaReceiver` 删除私有载荷，先发布清理后的 `pending`，后台验证原件后再发布 `ready` 或固定摘要的失败状态。完成回调等待初始投递结束，等待和 emitter 调用均不持有 delivery/owner 锁；初始化失败不会使文字接收流退出。
4. `anti_recall_image` / `anti_recall_file` 按账号、连接、会话、原消息编号关联撤回。撤回先到时等待本条媒体完成，成功后最多补发一次；缺少缓存、校验失败或连接已停止时不补发。

Linux 声明 `image.recall.receive`、`file.recall.receive`、`voice.recall.receive`。未完成与失败状态供消息监控和防撤回插件使用；当前连接完整校验的 ready 媒体另通过 `image.receive` / `file.receive` / `voice.receive` 向普通插件单次分发。加载报告 `local_voice` 的发送桥接后开放 `voice.send`；语音完整闭环仍以本页的实机验收状态为准。Windows 后端保留现有通用能力，并提供专用别名供共同插件声明依赖。

## 语音原件与语音条

`LinuxVoiceReceiver` 只把完整且通过校验的 SILK 保存为本连接的私有缓存，最多 60 秒、256 KiB，默认最多 128 条、合计 32 MiB。没有完整音频时发布不可用状态，不把元数据当作可恢复的语音。此次实测收到 type 34，但新消息附带的 `ImgBuf` 未提供可用音频，现已通过当前账号 `media_*.db` 的 `VoiceInfo` 只读补充读取：按精确会话及 `svr_id` 查询，密钥仅留在内存，结果仍须验证封装、声明长度和时长。该补充路径已通过真实 SessionLease 链路完成新群语音自动缓存；撤回后仅补发一条 type 34，接收端确认原声可播放。

发送命令 `W` 使用当前账号绑定和原生协程检查，读取完整私有 SILK 后构造 type 34 对象；原生对象深拷贝音频字节。1 秒测试音已通过群接收端播放验证。原生接口成功只表示发送阶段回执，最终送达仍需接收端确认。完整偏移、协议与边界见 [Linux 语音](VOICE.md)。语音防撤回不执行 ASR、LLM 或 TTS；`voice_reply` 是已有文字回复经过配置的模型和 TTS 生成语音的另一条链路。

## 原生表情发送

`send_bridge.c` 的 `O` 操作只接受经过 Python 完整解码校验的私有 GIF 快照，再由原生侧检查文件所有者、权限、大小、GIF 头尾。需要已绑定当前登录账号；桥接握手报告 `local_emoticons` 后，管理台才开放 `emoticon.send`。

静态调用链与偏移以 `send_bridge.c` 注释为准，当前已核对：

- 本地路径分类 `0x6f803b0`，type 47 DTO 构造路径 `0x6f8054c`。
- `0x6f809c6` 将 `image_info+24` 复制到 `DTO+0x5e8`，再设置路径和目标。
- 调度 lambda `0x6f91ed0` 在 `0x6f91fe3` 调用消息管理器；发送等待路径为 `0x64d6ba0` / `0x64d6bd0`。
- 实现使用 type 47 DTO 构造器 `0x496bb00`，核对 vtable `0xa8a11b8`，通过 `0x64ccca0` 发起消息。

这些偏移不是跨版本 API。动态表情实际撤回后能够以表情消息恢复并播放，补充了静态链路证据；未知版本仍拒绝加载。

## 图片下载范围

机器人开始接收前绑定 1–64 个精确会话 ID，允许好友私聊或明确群会话，并绑定当前账号。缺少完整本地原件时，通过原生消息上下文请求下载，再读取和校验当前账号缓存。白名单为空、过大或桥接不具备所需能力时，不会退化为无限制下载。

原生上下文最多保存 16 条。范围更新、清理、上下文查询及下载使用 `scope_generation` 区分连接代次；账号退出、切换以及旧连接的迟到请求不得沿用新范围。群路径要求消息来源字段与明确允许的群及当前账号对应，不按相似昵称或前缀扩大匹配。下载后仍须通过完整长度与 MD5 校验，才生成可供防撤回使用的私有快照。

已在加载新桥接后实机验证：另一个账号向明确白名单群发送新图片，Linux 端不点开图片，管理台显示后台下载后的完整校验缓存；撤回后原生 type 3 补发成功，接收端确认能够正常打开。该结果覆盖群图片后台下载到撤回恢复的完整链路。

## 限额与隔离

| 项目 | 默认限制 |
| --- | --- |
| 文字内容 | 每条最多缓存 2000 字符，发送阶段再按接口字节上限分段 |
| 私有媒体缓存 | 每个机器人连接最多 128 个文件，合计 256 MiB |
| 接收队列 | 16 项 |
| 单次扫描 | 最多 4096 个路径，读取总量最多 64 MiB |
| 图片 | 每张最多 20 MiB，完整 MD5 匹配后才返回 |
| 文件 | 类型 6/74；缓存预算最多 256 MiB，但默认单次 64 MiB 扫描预算使大于 64 MiB 的单个文件无法完成恢复 |
| 目录与权限 | 仅当前账号目录；私有缓存目录 0700、文件 0600 |

文件只接受已核对的 `msg/file/YYYY-MM/原文件名` 布局，以及微信重名保存的 `文件名(N).扩展名`（N 为正整数）；重名候选仍须通过原消息的完整 MD5 和长度校验，补发保留原消息文件名。图片仅根据消息提供的长度和摘要选择候选。拒绝符号链接、非本用户文件和硬链接，读前读后核对文件身份与大小，复制到私有缓存后才交给插件。缓存淘汰只移除本接收器创建的文件，停止连接后清理本轮缓存。文件尚未落盘时不会主动请求下载。

文件发送另存独立的私有快照，保留原文件名和内容。原生消息管理器的返回不代表异步上传完成，因此提交 `F` 后，无论返回成功或结果不明，都保留该快照直至确认绑定微信进程退出。每个发送器最多保留 64 个文件、合计 64 MiB；满额拒绝新请求，不淘汰可能仍在上传的文件。关闭机器人不会删除在途快照；管理台关闭并等待微信进程退出后才清理。本轮生命周期回归包含插件临时文件删除后延迟读取快照的验证；实机重名附件经完整校验后，撤回触发一次同名补发，接收端确认收到且能下载打开。原生接口成功和本地 outgoing 记录仍不应单独视为送达保证。

V2 缓存解密临时读取经版本、PID 和账号核对的微信进程密钥，读取后再次核对身份；密钥不写入磁盘或日志。原始 XML、CDN 凭据和任意原始异常文本不进入媒体监控消息。运行时私有目录、媒体、微信安装包、编译产物和真实账号数据均不属于发布内容。
