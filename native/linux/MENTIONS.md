# Linux 群艾特发送依据

适用 ELF：官方 Linux 微信 4.1.13.26 x86_64。
SHA-256：`2749535f299ba67feb8ef80cab898bb0531fa8f376b16f8a72db706811c84132`。
Build ID：`d62bde21b26c5928e7dea826271e21a542b755b5`。
以下地址均是模块相对虚拟地址，不是文件偏移。

## 原生调用

普通 SDK 入口 `0x6f19410` 只读取 `chat_id` 和 `content`，不能靠添加 JSON 字段发送艾特。
下游 `0x6f93c80` 创建文本消息，使用构造函数 `0x4a040a0`。

| 位置 | 含义 | 静态依据 |
| --- | --- | --- |
| 对象 vtable | `0xa8a10c8` | 文本消息构造器 |
| `+0xe4` | 消息类型 1 | 文本消息创建路径 |
| `+0x90` | 目标会话字符串 | 文本消息创建路径 |
| `+0x5c8` | `content` 字符串 | `0x60ace38` 注册字段 |
| `+0x5e0` | `at_user_list` 字符串 | `0x60ace8a` 注册，属性 vtable `0xa8a3448` 的函数 `0x60bab90` 返回该字段名称 |

拷贝构造 `0x60b4100` 和析构 `0x60acd70` 确认两个字段采用 24 字节 libc++ 字符串。
按已有媒体路径取得消息管理器（`0x60421e0` → `0x619ce90` → `0x61ad930`），
在微信协程中调用 `0x64ccca0`，销毁状态与共享对象。成功回调表示原生接口受理，不能单独证明对方收到提醒。

## 桥接与验证

命令 `M` 使用现有长度前缀协议，正文是 `群ID\n逗号分隔成员ID\nUTF-8正文`。
`H` 握手显式报告 `group_mentions`，旧桥接不会静默退化为普通文字。
发送前检查指纹、PID/UID、当前账号绑定、协程上下文；Python 层检查白名单和会话。
桥接再次限制群目标、1–8 个唯一成员、禁止系统账号和 `notify@all`、正文最多 1023 字节。
超时或连接丢失返回结果未知，不自动重发。

合成 fixture 覆盖实际 C 命令解析与调度、中文/换行/emoji、成员名单、旧账号拒绝、原生拒绝、
丢失回调、超时不重试；插件经 Linux 后端发送长文本时仅第一段艾特。
面板测试覆盖去重和过期会话，多账号测试覆盖白名单、账号变更及停止后的拒绝。
fixture 不执行专有 ELF 内部函数；真实群提醒必须另行做接收端验证。
