# Linux 语音：原生发送与防撤回接收

仅针对官方 Linux 微信 **4.1.13.26 x86_64**。沿用可执行文件 SHA-256、Build ID、原生入口检查、账号绑定，以及本地通信的 PID/UID 检查；这里的偏移不能用于其他版本。

## 当前验证结果

| 链路 | 状态 |
| --- | --- |
| 原生 type 34 发送 | 已实现；1 秒测试音发送到明确授权的测试群，接收端确认可以播放 |
| 语音消息识别 | 已实机收到 type 34 元数据；当前样本的新消息附带 `ImgBuf` 未提供可用完整音频 |
| 完整入站音频缓存 | 当前账号语音数据库补充读取已完成；新群语音通过真实 SessionLease 接收链自动缓存，实机验收通过 |
| 语音撤回后补发原音 | 群短语音完整缓存后撤回，仅补发一条 type 34；接收端确认原声能够播放，闭环实机验收通过 |

原生发送返回成功、监控出现 outgoing 或识别到语音类型，都不能单独证明音频已送达或可恢复。

## 能力与用途

Linux 后端提供专用 `voice.recall.receive`，完整音频只供消息监控和 `anti_recall_voice` 使用，不声明通用 `voice.receive`。发送桥接握手 `H` 报告 `local_voice: true` 后，后端开放 `voice.send`、`friend.voice.send`、`group.voice.send`。

防撤回直接重新发送缓存的原 SILK，不进行 ASR、LLM 或 TTS。已有 `voice_reply` 是文字输入经配置的模型回复及 TTS 合成语音的另一条链路，需要自己的模型、TTS 服务和群音色设置；提供原生发送能力不代表能够识别收到的语音。

## 发送协议与对象生命周期

`W` 使用现有认证本地通道，长度字段为网络字节序 uint32，正文为 ASCII：

```text
target_id\nduration_ms\nhex(UTF-8 absolute path)
```

`V` 仍保留为旧的无正文验证探针。`W` 必须先绑定当前登录账号并通过原生协程 dry run。Python 层还核对本连接允许的目标；原生侧在读取和提交之间再次确认当前账号。

共享 `prepare_voice` 可将支持的单声道 PCM WAV 转为 SILK，或将标准 SILK 转为 Tencent 封装。原生边界仅接受 `0x02 + #!SILK_V3`，最多 **262144 字节（256 KiB）**、**60 秒**；逐包检查有符号 16 位长度、完整包边界及 `包数 × 20ms == duration_ms`。这些检查验证封装，不解码证明任意外部音频载荷可播放；通用多帧 SILK 包不在此约定内。

输入必须是当前用户拥有的普通私有文件，拒绝符号链接、硬链接及组/其他用户权限，并核对读前读后的大小和修改时间。所有字节在提交前完成有界复制。原生语音 DTO 再深拷贝音频，不依赖发送后的源路径；正常回执后可清理临时快照。连接超时或断开使结果不明时，Python 保留本次私有快照并阻止该连接再次发送语音，不自动重试。

## 接收与数据库补充读取

接收桥接使用 `HLV1` 在原消息编号和 XML 之外携带可选音频。当前直接读取路径为 new_sync `+0x30` 的 `SKBuiltinBuffer_t`：长度 `+0x10`，字符串指针 `+8`。只有稳定、有界、长度一致且带 SILK 头的数据才复制；缺少音频不丢弃原消息。

实机样本表明不能假设每条语音都会在此处携带完整音频。补充读取使用当前账号 `media_*.db` 的 `VoiceInfo`：通过 `Name2Id` 确定精确会话，再按 `chat_name_id` 和消息 `svr_id` 精确匹配。采用只读 SQLCipher 连接、新事务及进程/账号/目录校验；数据库密钥只留在内存，不写磁盘或日志。没有唯一、完整且可校验的音频时返回不可用，不按最近时间、相似昵称或其他会话猜测原件，也不臆测未知 `data_index` 的分片规则。

`0x6673c60` 的 ORM 注册已核对以下布局，用于解释数据库列，不作为直接读取运行中对象的接口：

| 列 | 对象偏移 |
| --- | --- |
| `chat_name_id` | `+0x00` uint32 |
| `create_time` | `+0x04` uint32 |
| `local_id` | `+0x08` uint32 |
| `svr_id` | `+0x10` uint64 |
| `voice_data` | `+0x18` 字节 vector，三个指针 |
| `data_index` | `+0x30` libc++ string |

`0x6673b80` / `0x6673bb0` 复制或移动音频 vector；字段 getter `0x6674750` 和 setter `0x6674740` 对应 BLOB。`0x666b0a0` 在索引为空时补 `"0"`。完整音频仍须经过共享 SILK、XML 声明长度和时长校验，接收计时允许一帧（20ms）差异。

接收器为每个机器人连接创建独立 0700 目录、0600 文件，默认最多 128 条、合计 32 MiB，队列最多 16 项。只处理当前账号、连接及允许会话；停止后清理本轮缓存，旧连接回调不能触发新连接补发。公开消息中不保留原始 XML、音频字节、凭据或底层异常。只有缓存 `ready` 才具备补发原音的条件。数据库补充读取已完成，新的群语音经过真实 SessionLease 链路自动缓存，撤回后单次补发并经接收端确认原声可播放。

## 离线验证与复测

新增发送测试 9 项通过，覆盖真实分支编译、原始文件删除后已复制字节仍在、标准 SILK 规范化、账号切换、授权、dry run、截断和超限、私有文件、失败及超时保留。既有发送/媒体/表情/图片范围/文件生命周期 67 项及艾特/群消息 19 项通过。生产发送桥接通过 `-Wall -Wextra -Werror` 编译。

```bash
PYTHONPATH=tests:native .venv/bin/python -B -m unittest test_linux_voice_send -v
```

离线 fixture 使用合成封装，只验证边界与调用行为，不证明合成载荷能播放。实机已确认 1 秒测试音可播放，并完成群短语音从自动缓存、撤回关联、单次 type 34 补发到接收端原声播放的验收。数据库只读预检曾在约 1.04 秒内取得 3527 字节、2760ms 的完整样本；随后新的群语音通过真实 SessionLease 链路验证，产品结果不依赖预检脚本。

本轮实机范围为 1 秒测试音和约 2–5 秒群短语音；60 秒与 256 KiB 上限仅有边界校验，不代表极限实测。Linux 私聊语音防撤回仅有离线验证，尚未单独实机验收。付费 TTS 服务及文字模型到 TTS 的完整在线链路未实测。
