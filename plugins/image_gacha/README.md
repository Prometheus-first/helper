# 随机抽卡

在机器人的私聊或已配置的群里发送 `/抽卡`，从网站目录随机抽取一条提示词，使用自己的图片生成接口出图并回复原会话。

## 配置与启用

1. 复制项目根目录的 `image_generation.example.json` 为 `.runtime/image_generation.json`，填写自己的 OpenAI 兼容图片生成接口地址、API key 和模型名称。已有生图配置可以直接复用。
2. 在网页管理台选择已连接的机器人账号，确认 `image_gacha` 插件已启用。插件默认启用，也可在控制台执行 `enable image_gacha`。已运行的机器人需要重新加载插件或重启机器人。
3. 在私聊中发送 `/抽卡`。群聊需要先加入成员配置，并满足账号的收发范围设置。

每次命令抽取一条提示词，生成一张图片。插件独立启停，普通 `/生图` 插件可关闭。多账号共用项目根目录的生图配置，插件启停和群范围按账号管理。

生图渠道和重试沿用 [AI 生图](../image_generation/README.md) 的实现。多个渠道或失败后的重试可能产生额外费用，首张成功图片回复原会话。最多同时处理 5 个抽卡任务，另可排队 8 个；抽卡和普通生图各自使用任务队列。停止插件、切换账号或微信连接后，旧任务停止发送。

## 提示词目录与数据

提示词来自 [网站目录](https://image.52131415.xyz/catalog.json)，每条记录等概率抽取，允许重复。程序将选中的字符串原样传给已配置的生图服务商。目录请求只发送固定请求头。

提示词保留在内存中，目录缓存 5 分钟，不在聊天中展示，也不写入日志或本地提示词文件。目录不可用、过大或格式错误时，本次抽卡提示失败，后续手动命令可重新读取。网站内容和可用性由目录提供方维护。

API key 由使用者自行配置在 `.runtime/image_generation.json`。该目录已被 Git 忽略，分享项目时应排除运行配置、聊天数据和媒体缓存。

正常发送后清理临时图片。发送结果未知时，图片会暂存在项目根目录的 `.runtime/generated_images/`，供微信完成读取。程序停止且确认发送完成后，可以清理这些图片缓存。

## 验证

离线测试使用合成提示词和模拟生图接口，覆盖长提示词原样传入、目录缓存、无效目录、会话切换、独立插件启停以及失败信息脱敏。测试命令为 `python -B tools/run_tests.py --pattern test_image_gacha.py`。实际出图取决于使用者配置的模型接口和微信连接。
