# 防撤回补发

默认开启。有人撤回消息后，在原群聊或私聊发送：

```text
撤回的消息是：原来的文字
```

文字、微信内置表情（如 `[微笑]`）和 emoji 原样补发。表情包（类型 47）在收到时异步缓存，撤回后直接重新发送原表情包，不再额外发送一条“[表情]”提示；无需单独启用表情插件，也不需要大模型或 API 密钥。

表情包只使用消息里携带的已支持微信 CDN 原件地址，检查声明大小和 MD5，不访问本地微信账号目录，不导出收藏。收到表情包只缓存，不自动回复；撤回通知先到时等待缓存完成，再补发一次。GIF 结束符后的微信附加标记会按块结构剥离，动画图像数据不变；PNG/WXGF 沿用现有转换器生成可发送 GIF，WXGF 需要可选解码依赖。缺少原件地址、下载失败、不支持的格式或缓存已淘汰时，仍用 `[表情]` 类型提示，不把缩略图冒充原件。

原始表情包最多 20 MiB；可发送 GIF 最多 1 MiB、宽高不超过 1024、最多 300 帧和累计 6400 万像素。每个插件实例最多缓存 128 个不同表情包或 64 MiB GIF，先达到的限额生效。GIF 缓存在内存，发送使用临时文件，卸载时清空关联和缓存。CDN 地址、凭据及原始 XML 不写日志，也不交给模型。

语音和视频用类型提示；文件显示文件名（可用时），合并转发显示 `[合并转发]`。本插件不调用大模型、人格或语音合成。

`anti_recall_image` 和 `anti_recall_file` 是默认开启的两个独立插件，分别重新发送已下载的图片和文件。对应插件开启时，本插件省去图片/文件的类型文字提示，避免多发一条消息。关闭文本插件不影响两个附件插件；关闭附件插件后，本插件恢复对应的文字提示。

只处理插件启用后收到且仍在缓存中的原消息，每个插件实例最多缓存 1000 条。未捕获原文时不发送，重复撤回通知只补发一次。账号连接、群聊和私聊分别匹配，不跨会话查找，也不执行原文中的指令。插件卸载或重载会清空缓存。

在网页“插件管理”开关 `anti_recall`；控制台也可输入 `disable anti_recall` 或 `enable anti_recall`。会话白名单仍然生效。关闭插件后，管理台仍保留原来的“已撤回”标记。

已有防撤回版本升级本功能后，可在网页重载“文字防撤回”，或在控制台执行 `reload anti_recall`。本次未改核心模块和 DLL。
