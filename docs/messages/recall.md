# 防撤回与自动补发

`native_text` 后端会监听微信的撤回通知，按账号、会话和原始消息编号关联已收到的记录。群聊和私聊都可以使用，无需大模型或额外 API 密钥。

## 自动补发

`anti_recall` 插件默认开启。捕获原文后有人撤回，机器人会在原会话发送：

```text
撤回的消息是：原来的文字
```

在网页“插件管理”关闭 `anti_recall`，即可停止补发；控制台也可以输入：

```text
disable anti_recall
enable anti_recall
```

也可以在本地 `bot_config.json` 的 `plugins` 中设置：

```json
{
  "anti_recall": {
    "enabled": false
  }
}
```

该片段是 `plugins` 内的一个条目，保留其他配置。旧配置没有这个条目时，也会按默认值开启。

## 内容与范围

文字原样补发，不套用人格、不生成语音。长文字按微信发送接口的字节上限分段。图片、语音、视频和表情分别用 `[图片]`、`[语音]`、`[视频]`、`[表情]` 提示；文件显示文件名（可用时），合并转发显示 `[合并转发]`，本插件不重新发送附件或逐条补发合集。

会话白名单 `chat_allowlist` 继续生效：非空时，只在其中的会话缓存并补发；为空时，适用于收到的所有会话。群聊功能列表不额外限制本插件。多机器人账号、不同群及私聊分别匹配，不按相似文字或昵称查找。

插件只缓存启用后收到的最近 1000 条原消息。找不到原消息时不补发；同一撤回通知在去重缓存中只发送一次。未捕获原文、超出缓存、缺少原始编号或已切换连接的消息都不会跨连接补发。卸载、重载插件或重启程序会释放插件缓存。

## 管理台标记

消息监控会保留已经捕获的原内容、发送者和记录时间，并显示“已撤回”。合并转发的展开记录一起标记，下载完成后仍保留撤回状态。未捕获的原消息显示“原消息未捕获”。

管理台标记独立于补发插件。关闭 `anti_recall` 后仍能查看撤回标记；控制台运行 `main.py` 时也能使用补发插件。微信窗口本身仍执行正常撤回，已保存的媒体沿用原接收目录，管理台不展示媒体预览。

## 升级与验证

升级前停止机器人并关闭整个管理台，再覆盖代码和桥接 DLL，保留自己的配置与数据目录。重新打开管理台、启动机器人后，发送一条测试文字，等监控出现后撤回；应保留原记录，并收到“撤回的消息是：测试文字”。不要只热重载插件，核心分发代码和 DLL 也需要重新加载。

微信 4.1.15.13 的群聊撤回监听与管理台标记已实机验证；自动补发、私聊关联、去重、白名单、连接隔离和媒体类型提示通过离线测试，发布时未向真实会话自动发送补发测试。
