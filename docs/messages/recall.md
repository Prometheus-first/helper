# 防撤回与自动补发

`native_text` 后端会监听微信的撤回通知，按账号、会话和原始消息编号关联已收到的记录。群聊和私聊都可以使用，无需大模型或额外 API 密钥。

## 自动补发

`anti_recall` 插件默认开启。捕获原文后有人撤回，机器人会在原会话发送：

```text
撤回的消息是：原来的文字
```

图片和文件由两个独立插件处理，默认也开启：

| 插件 | 撤回后的行为 |
| --- | --- |
| `anti_recall` | 补发原文字；其他媒体可使用类型提示 |
| `anti_recall_image` | 重新发送已下载的图片 |
| `anti_recall_file` | 重新发送已下载的普通文件附件，保留原文件名 |

三个插件可在网页“插件管理”分别开关，也可使用 `enable <插件名>`、`disable <插件名>`。图片/文件插件无需文本插件保持开启；对应附件插件工作时，文本插件不会再额外发送 `[图片]` 或 `[文件]` 提示。

在网页“插件管理”关闭 `anti_recall`，即可停止补发；控制台也可以输入：

```text
disable anti_recall
enable anti_recall
```

也可以在本地 `bot_config.json` 的 `plugins` 中设置：

```json
{
  "anti_recall": {
    "enabled": false
  }
}
```

该片段是 `plugins` 内的一个条目，保留其他配置。旧配置没有这个条目时，也会按默认值开启。

## 内容与范围

文字原样补发，不套用人格、不生成语音。长文字按微信发送接口的字节上限分段。语音、视频和表情仍只显示类型提示，合并转发显示 `[合并转发]`；本次不逐条补发合集。关闭图片/文件插件且文本插件仍开启时，恢复 `[图片]` 或文件名的文字提示。

图片和文件复用接收器的独立磁盘缓存，撤回后重新发送附件本身，不把附件作为普通文件路径文本发出。单个附件沿用现有 20 MiB 限制；图片清晰度以实际下载到的版本为准。文件发送使用临时快照还原安全文件名，不带接收缓存的随机前缀，调用结束后清理该快照。

如果撤回通知先于下载完成到达，插件会等同一条附件下载成功后补发。尚未收到的历史附件、下载失败、缓存被清理或被替换的文件都不能恢复；不会重新从撤回后的服务器记录强行获取附件。普通链接、合并转发等分享不当作文件处理。

会话白名单 `chat_allowlist` 继续生效：非空时，只在其中的会话缓存并补发；为空时，适用于收到的所有会话。群聊功能列表不额外限制本插件。多机器人账号、不同群及私聊分别匹配，不按相似文字或昵称查找。

三个插件各自缓存启用后收到的最近 1000 条相关原消息，以及最多 1000 条撤回去重记录。附件插件缓存文件引用，不额外长期复制一份附件。找不到原消息时不补发；同一撤回通知在去重缓存中只发送一次。未捕获原文、超出缓存、缺少原始编号或已切换连接的消息都不会跨连接补发。卸载、重载插件或重启程序会释放插件关联记录，原接收文件仍由接收缓存管理。

## 管理台标记

消息监控会保留已经捕获的原内容、发送者和记录时间，并显示“已撤回”。合并转发的展开记录一起标记，下载完成后仍保留撤回状态。未捕获的原消息显示“原消息未捕获”。

管理台标记独立于三个补发插件。关闭它们后仍能查看撤回标记；控制台运行 `main.py` 时也能使用补发插件。微信窗口本身仍执行正常撤回，已保存的媒体沿用原接收目录，管理台不展示媒体预览。

## 升级与验证

升级前停止机器人并关闭整个管理台，再更新代码，保留自己的配置与数据目录。重新打开管理台、启动机器人后，发送一条测试文字，等监控出现后撤回；应保留原记录，并收到“撤回的消息是：测试文字”。这次修改包含核心消息分发，只热重载插件不能完整生效。

图片/文件插件升级需要重新打开整个管理台以加载新的核心分发；本次附件补发无需更换 DLL。测试时分别发送一张图片和一个普通文件，等待接收状态为 `ready` 后撤回，应收到重新发送的图片和文件，文件名与原附件相同。

微信 4.1.15.13 的群聊撤回监听、管理台标记、图片撤回后重发和普通文件撤回后重发已实机验证。私聊关联、下载完成前撤回、文件名保留、去重、白名单及连接隔离使用本地真实附件、模拟下载器和内存发送端做离线验证。
