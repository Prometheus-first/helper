# 常见问题

## 必须安装 Visual Studio 吗

日常运行不需要。项目提供已编译的桥接 DLL，只需匹配的 Windows 微信、64 位 Python、Python 依赖和 Microsoft Visual C++ x64 运行库。修改原生源码并重新编译时才需要 MSVC 工具链。

## 微信版本不匹配怎么办

当前适配 4.1.15.13、4.1.15.56 和 4.2.0.11 的指定构建。4.2.0.11 尚未开放联系人扫描、表情包、好友申请、群管理和朋友圈点赞评论等功能。框架核对核心 DLL 指纹，并使用对应版本的原生地址和账号缓存参数。未适配的版本或指纹会停止加载；不要删除检查或把旧地址直接套到新客户端。更新框架后请先退出旧管理台，再自行重新打开 `start_web.bat`。

## 手机发了测试消息，电脑看得到但监控没有

请用另一个微信账号向当前电脑登录账号发消息，或在共同群里发消息。4.1.15.56 实测中，同账号手机发送的同步文本未经过当前来信监听入口；不能用这种同步消息判断普通来信 Hook 是否工作。当前接收不补拉启动前的历史消息。

## 没登录时不知道 wxid 怎么填

首次使用将 `wechat_account` 保持 `null`。网页管理台会列出已登录微信，点击对应账号“启动”即可，不必手填 wxid。使用 `main.py` 时，单个已登录账号自动识别，多个账号在终端选择。两种方式都不需要发 `init`。

## 新群没反应怎么办

1. 让群里发送一条普通文本，从网页“消息监控”或运行日志复制群 ID。
2. 在网页“群聊与会话”添加群 ID，或修改 `members_config.json` 的 `groups`。
3. 如果 `chat_allowlist` 非空，把群 ID 也加入白名单。
4. 确认对应插件启用；模型功能还需要有效模型配置。
5. 停止并重新启动对应机器人，使配置生效。

操作示例见[添加一个群](./account-and-groups.md#添加一个群)。

## 提示重复运行或桥接 DLL 已加载

先在已有运行窗口输入 `quit`，等到“框架已停止”。同一微信进程不能同时连接两个机器人项目副本。

当前代码在正常退出时清理桥接；关闭窗口会请求清理，异常结束时由隐藏守护尝试清理；下次启动还会检查本项目残留。原生任务仍在执行时会保留模块并重试，避免提前卸载。

`.runtime/bot.lock` 的存在本身不代表重复运行，不需要手动删除。其他目录加载的桥接不会被当前项目卸载。问题持续时查看 `logs/bot.log` 与 `logs/bridge_watchdog.log`，确认旧实例已退出；必要时在停止机器人后重启微信。

## 为什么不能用群名直接发送

可见昵称和群名可能重复或改变。发送接口接受实际会话 ID：文件传输助手为 `filehelper`，群 ID 以 `@chatroom` 结尾。使用 `chats` 或实时日志取得 ID。

## 为什么昨天的聊天总结不了

当前总结只覆盖当天、指定群、框架实际收到并保存的有效文字。默认每天北京时间 0 点清理旧文本；停机期间不会补拉历史。`/清空` 也会清除本群文本，但不会删除称呼绑定。

## 图片和表情接口有什么区别

`send-image` 发送普通图片，`send-emoticon` 发送原生类型 47 表情。动态 GIF 表情应使用后者，并满足大小、尺寸和帧数限制。详见[表情提取与发送](../messages/emoticons.md)。

## WAV 或 MP3 为什么发不出去

语音支持 SILK v3，以及单声道 16-bit PCM、采样率为 8/12/16/24 kHz 的 WAV。WAV 转码需要安装 `requirements-voice.txt` 中的可选依赖。

目前不支持 MP3、AAC、立体声和其他 WAV 编码；单条最多 60 秒。修改扩展名不会改变编码。详见[语音发送](../messages/voice.md)。

## 网站是否需要运行机器人才能访问

文档网站由 GitHub Pages 托管，浏览器可直接访问。网页管理台是另一个本机服务，需要双击 `start_web.bat` 或运行 `python web.py`；机器人也始终运行在你的 Windows 电脑上。控制台入口 `python main.py` 继续保留。

## 消息监控没有旧消息或提示尚未加载

监控只显示机器人运行后实际收到的消息和发送接口已接受的回复，不读取微信旧历史。每个账号保留最近 1000 条内存缓存；关闭管理服务后不会保留这份监控缓存。用于聊天总结的数据库不受影响。

升级后若提示监控尚未加载，先停止所有机器人并关闭管理台，再重新启动服务、刷新网页。仅刷新浏览器不会重载旧的 Python 工作进程。

## 更新前需要备份什么

保留本地四份配置：`bot_config.json`、`members_config.json`、`llm_config.json`、`tts_config.json`，以及 `.runtime/` 中需要保留的数据。多账号的配置、历史和账号目录索引也保存在 `.runtime/robots/`，需要一起备份。

更新前先停止所有机器人并关闭管理台；控制台启动时输入 `quit`。确认退出后再拉取代码，避免旧进程占用桥接 DLL。发生 Git 分支冲突时保留本地修改并处理合并，不要用强制覆盖作为日常更新方式。上述私有配置、聊天数据与日志均不应提交到公开仓库。
