# 本地网页管理台

在项目目录运行：

```powershell
python web.py
```

程序会打开 `http://127.0.0.1:8765`。管理台自动列出已登录的微信，由你勾选并点击“启动所选”后才连接对应账号。网页使用项目现有的 JSON 配置和 `.runtime/` 数据，不需要安装额外的 Web 框架或构建前端。

Windows 也可以直接双击项目里的 `start_web.bat`，自动打开浏览器。启动器依次查找 `WXBOT_PYTHON` 指定的解释器、项目 `.venv`、系统 `python` 和 `py -3`；失败时保留窗口显示原因。关闭服务请按 Ctrl+C。

也可以使用 PowerShell 启动脚本：

```powershell
.\start_web.ps1
```

左侧 helper 品牌右侧显示版本 `v1.2`。右上角可切换亮色／暗色。首次跟随系统，手动选择后由浏览器记忆。

## 启动微信并获取登录二维码

运行概览中点击“登录微信”，管理台会启动微信并显示登录二维码；用手机微信扫码并确认后，账号会出现在已登录列表中。你仍需选择账号并启动机器人。当前支持已核对指纹的微信 4.2.0.11 和 4.2.0.12，微信登录窗口需要保持打开且未最小化。微信有时显示登录按钮而不是二维码，此时请在微信窗口操作并在手机上确认。

管理台也提供本地接口。请求需携带页面的 `X-Helper-Token`，请求和二维码只应留在本机：

| 接口 | 用途 |
| --- | --- |
| `POST /api/wechat-login/start` | 请求体 `{}`，启动微信并返回 `attempt_id` 和 `pid` |
| `POST /api/wechat-login/attach` | 请求体 `{"pid": 1234}`，使用已打开的未登录微信进程 |
| `GET /api/wechat-login/status?attempt_id=...` | 查询状态；`qr_available` 时返回 PNG 的 `qrcode_base64` |
| `POST /api/wechat-login/cancel` | 请求体 `{"attempt_id":"..."}`，释放读取句柄，不退出微信 |

状态还包括 `starting`、`waiting`、`logged_in` 和 `exited`；`logged_in` 返回当前进程的 `wxid`。登录尝试保留 5 分钟，超时后可重新开始；二维码本身的有效期由微信决定，过期时需要在微信刷新。二维码内容只在内存中处理，不写入日志和文件，也不自动启动机器人。

## 同时运行多个机器人

无需手填 wxid、手动绑定账号或先创建机器人：

1. 在电脑微信完成需要使用的账号登录。
2. 在“已登录微信”中核对微信名、wxid 和进程，勾选需要运行的账号。
3. 点击“启动所选”，可一次启动多个账号；未勾选的账号不受影响。
4. 首次使用的新账号，可先在顶部“当前账号”选择它，配置群聊、模型和插件，再点击该行“启动”。切换账号只准备配置，不启动机器人。
5. 顶部“当前账号”用于切换插件、群聊、模型和日志的管理对象。每行“启动”只启动该行账号，运行后变为“停止”；不改变顶部选择，也不影响其他机器人。

原有账号会自动对应已有配置，保留密钥、群聊、插件和历史，重新登录后进程 PID 变化也能找到原配置。首次使用且默认配置尚未对应账号时，所选第一个账号使用默认配置；之后的新账号使用空模板，不复制其他账号的密钥、群聊或历史。每个机器人由独立 Python 工作进程运行；配置、数据库、语音与媒体数据、日志按工作目录分别保存。附加机器人位于 `.runtime/robots/<实例ID>/`，列表保存在 `.runtime/robots/index.json`，均被 Git 忽略。题图缓存及少量原生请求临时文件还会使用项目 `.runtime/`，按账号或随机请求 ID 区分。

页面约每 10 秒识别一次账号，也可手动刷新。刷新或重新打开页面不会自动勾选、启动机器人；关闭浏览器后，已经运行的机器人继续运行。批量启动会逐个显示提交结果，某个账号失败不影响其他所选账号；请求已提交后，实际连接状态以列表和日志为准。

如果账号退出或进程变化，旧选择会失效，需要刷新后重新选择。同一账号的重复登录进程或重复配置会被标记并禁止启动；同一微信进程仍有原有跨项目占用保护。微信扫码和手机确认在微信客户端完成。`python main.py` 的控制台启动方式继续使用原来的账号选择和保存逻辑。

退出主管理服务会通知全部工作进程正常停止并清理连接；关闭浏览器不会停止机器人。主进程意外退出时，工作进程会因父进程管道关闭而开始清理，原生退出守护继续兜底。

## Windows 微信自动恢复

在「运行概览」选择账号后，可以在「微信自动恢复」保存当前账号的设置。每个账号默认开启，旧配置缺少 `windows_auto_recovery` 时同样开启。先停止该账号的机器人，再取消勾选并保存即可关闭。

Helper 用独立进程句柄读取原生桥接的执行记录。同一原生调度或任务连续执行至少 90 秒，且账号和同一任务复查仍匹配时，才会重启对应微信进程。回包丢失、排队未开始和读取健康信息失败都不会触发重启。两次自动重启至少间隔 10 分钟，每小时最多 3 次。

Helper 确认旧进程退出后，使用原微信程序路径重新启动。如果需要登录，请在新窗口登录原账号。只在新进程身份和账号匹配后恢复机器人。Windows 微信若把启动请求转交给已有窗口，新实例无法确认时管理台会提示手动登录。结果未确认的原发送记录保留为 `unknown`，不会自动重发。

离线验证使用原生桩和合成进程。原生任务开始执行才会出现健康记录，退出后该记录清除。测试还验证了账号不匹配或执行编号已变化时不会触发重启、只结束目标进程、另一进程保持运行、旧机器人清理后才恢复、以及原请求状态保留。7 项 Windows 自动恢复专项测试和 66 项前端回归通过。本次验证没有操作真实微信账号。

## 页面功能

| 页面 | 功能 |
| --- | --- |
| 顶部账号选择框 | 切换管理对象、查看各账号运行状态 |
| 运行概览 | 发现已登录账号、逐行启动或停止、勾选批量启动；查看每个账号的连接、wxid 和进程；实时消息监控 |
| 插件管理 | 搜索插件、启用、停用、重载；编辑业务函数与 JSON 选项，保存生效或重置默认 |
| 群聊与会话 | 发送文字、选择成员进行真实艾特、查看群内身份；保存群 ID、群备注、会话白名单和记录开关；发现已收到消息的群 |
| 联系人 | 扫描并按账号保存，重启自动读取；搜索昵称、备注、微信号、wxid 和标签，查看个人资料 |
| 公众号文章 | 自动分页同步公众号文章列表，点击后自动加载正文和图片，阅读及导出 Markdown |
| 模型与语音 | 配置 DeepSeek 或 OpenAI 兼容接口、语音合成与文本随机等待 |
| 运行日志 | 实时查看日志、筛选警告与错误、暂停滚动、清空当前视图 |

概览页直接在已登录微信列表中展示状态和启停操作。顶部账号选择框包含已登录的新账号，首次选择时自动准备独立配置。插件使用列表展示功能、状态和操作，模型的超时等设置放在“高级选项”中。窄窗口下导航收进菜单，列表自动换行，所有操作仍保留。

管理服务断开时，页面会提示当前展示的是上次读取的信息，将状态标为“待更新”，并暂停依赖服务的操作；连接恢复后自动更新状态和恢复操作。若重新启动了管理服务，刷新浏览器以取得新的页面会话。

插件描述在机器人启动前后、启停和重载后都会保留，并可按描述搜索。图库功能显示为“图库图片”，可在插件管理中开关、重载或编辑业务函数与配置，指令与图源见[图库图片](../messages/gallery.md)。

升级后先正常停止机器人、关闭管理台，再重新打开 `start_web.bat`；只刷新网页或重载插件不会更新核心 Python 模块。

## 网页修改与重置插件

防撤回插件默认折叠在“防撤回”一行中，点击展开后可分别启停、配置或重置；搜索会显示匹配的插件。

在顶部选择机器人账号，进入“插件管理”，点击对应插件的“配置”。“业务代码”直接显示这个功能的处理函数，例如文字回复、发送图片、欢迎文案或生成总结；直接修改函数内的逻辑即可。初始化、连接、清单和其余源码不会显示。一个功能有多个业务函数时可按用途切换，“配置”页编辑该插件的 JSON 选项。点击“保存并生效”或按 Ctrl+S 保存。

机器人运行时保存会自动重载该插件，无需重启机器人。机器人停止时先保存，下次启动生效；停用的插件保持停用，除非同时将 `enabled` 改为 `true`。Python 语法、JSON 或插件加载失败时保留原代码和配置，编辑器显示错误，未保存的输入仍可继续修改。插件正在处理长任务时可能暂时无法重载，等任务结束后再保存。

“重置”或编辑器内的“重置插件”会先显示确认，再恢复当前安装版本的默认代码和该插件的模板配置。只影响所选账号的这一个插件，账号、群聊、模型密钥、聊天记录及其他插件配置保留。重置后的启用状态也按默认配置恢复。

框架会传入函数需要的消息、回复接口和已经准备好的业务数据。保留函数名称、参数和装饰器，只修改函数内部；保存时只替换对应函数，其他源码原样保留。修改按账号存放在各自工作目录的 `.runtime/plugin_code/`，不会改写项目内 `plugins/` 的默认代码，其他机器人不受影响；原版本留作本地备份。两个页面同时编辑时，旧版本会提示重新读取，避免覆盖新改动。单个业务函数最多 256 KiB；无需安装额外编辑器依赖。

升级本功能后需先正常停止机器人、关闭管理台，再自行打开 `start_web.bat`。

群聊备注按机器人账号保存在本地，不会修改微信中的群名称。在“群聊与会话”里为群 ID 填写备注，停止机器人后保存；备注会显示在已发现的群和发送消息的会话列表中。

点击“发现群聊”后，群 ID 和微信群名称会保存到本地，重新打开管理台时自动读取。后续发现按群 ID 合并，更新已有名称并加入新群；由于微信缓存可能不完整，一次未扫到的群不会自动删除。手动填写的群聊备注优先显示，不会被扫描覆盖；已发现的群不会自动加入插件支持列表。

## 发送文字和艾特成员

在顶部选中已连接的机器人，进入“群聊与会话”→“发送消息”：

1. 选择群聊或好友；列表合并当前账号已配置的群、本地保存的已发现群、本次连接发现的会话和文件传输助手。进入页面后会自动读取，也可以点击“刷新会话”。
2. 选择群聊后会读取当前群成员。可按昵称、wxid 或身份搜索，勾选要艾特的人，每条最多 8 人；不勾选则发送普通文字。
3. 输入正文并点击“发送”。艾特使用真实成员 ID 和当前群昵称，支持微信的艾特通知；私聊不支持艾特。

成员表显示“群主”“群管理员”“普通群友”。成员缓存尚未就绪时仍可发送普通文字；需要艾特成员时，可以先在微信打开该群，再点击“刷新成员”。身份或完整名单尚未同步时显示未知或提示刷新。本群绑定称呼不改变真实群内身份，昵称也不作为权限依据。

超长正文按 UTF-8 字符边界拆成多条顺序发送，自动添加的艾特标签和通知只在第一条。每条沿用文本随机等待和会话白名单。发送状态独立查询，网络中断不自动重发；失败或结果不确定时先在微信核对，再决定是否重新发送。切换顶部账号会清空发送草稿和所选成员，已提交的发送仍属于原账号。页面加载、选择成员和刷新列表都不发送消息。

## 定时任务

在顶部选择账号，进入“定时任务”，选择任务类型并填写对应参数，再选择按分钟间隔或每天的本机时间，然后保存。可以编辑、启停和删除任务；列表显示下次执行时间和最近结果。当前内置发送文字和聊天总结插件的总结群聊；插件可以声明更多任务类型。会话 ID 可输入群 ID、好友 wxid 或 `filehelper`，输入框也提供已发现会话的候选项。

任务按机器人账号保存在本地，仅在管理台和对应机器人运行且微信已连接时执行；插件任务还需要相应插件已启用并加载。发送遵循会话白名单和文本发送节奏。关闭期间或断线时错过的任务不会补发，结果不确定时不会自动重试；同一任务上次还在运行时跳过重叠的下一次。编辑或重新启用任务会从保存时重新计算下次执行时间。已有文字任务继续有效。

## 扫描联系人

在顶部选择已连接的机器人，进入“联系人”，点击“扫描联系人”。页面读取当前电脑微信的本地好友缓存，显示昵称、备注、wxid、微信号和好友标签；点击行内“详情”可查看有值的性别、国家或地区、省份、城市、个性签名及好友描述。签名和描述分别显示，国家沿用微信缓存中的代码。

可搜索昵称、备注、微信号、wxid 和标签，或按好友标签筛选。每页显示 50 位联系人。没有标签时显示“无标签”；微信缓存中的标签名称暂时不能读取时显示“暂不可读取”，不会把它当作无标签。

联系人扫描目前已核对微信 **4.1.15.56 / 4.2.0.12**，支持基本资料、好友备注与已加载的好友标签。4.2.0.12 按该构建的联系人扩展资料、标签缓存身份读取；4.1.15.13 / 4.2.0.11 的完整联系人目录尚未适配。

页面打开、切换页面和搜索均不自动扫描，也不强制联网同步好友。名单是否完整取决于当前微信缓存；未显示预期好友或标签时，可先在微信打开“通讯录管理”，再重新扫描。

成功扫描后，联系人、备注和标签会按微信账号保存到当前机器人工作目录的 `.runtime/directory_cache/<账号摘要>/contacts.json`，群目录保存在同目录的 `groups.json`。重启管理台后自动读取，机器人未启动时也可搜索和查看联系人。重新扫描成功会整体替换联系人快照，更新新增、修改和已不在本次扫描结果中的记录；扫描失败保留旧文件与页面资料。名单仍受微信当前缓存完整程度影响。

不同账号的文件互相隔离。页面显示保存时间；连接断开后保留资料，但扫描和发送仍需要有效连接。只保存目录资料，不保存连接令牌、原始 XML 或媒体下载凭证，不写入运行日志。`.runtime/` 默认忽略提交，分享项目时请排除该目录。

## 检测单向删除

目前支持核心指纹匹配的电脑微信 **4.2.0.12 x64**。在顶部选定已连接的账号，进入「联系人」，先点「扫描联系人」，再点「检测单向删除」并确认。检测逐个处理当前账号的本机好友缓存，范围取决于微信已加载的名单。

**微信可能显示「你已添加了对方」的系统提示，并更新部分好友关系。** 此功能使用微信的好友验证操作，页面打开、刷新目录或查询结果都不会启动检测。

微信明确要求朋友验证（`-44`）时，对方会出现在「疑似被单向删除」列表中。其他失败或无法确认的结果计入「待核对」。连接中断时保留已经确认的结果，剩余好友等待手动发起检测。页面显示本次结果，刷新页面会清空列表。

受控的单人实测中，互为好友时微信接受了请求，对方单向删除后返回 `-44`。此前的批量实测出现了添加好友的系统提示。网页接入通过离线桩验证。

## 删除好友

目前仅支持核心指纹匹配的电脑微信 **4.2.0.12 x64**。在「联系人」页扫描当前账号的好友，打开目标的「详情」，点击「删除好友」，核对确认框中的操作账号和目标 wxid 后确认。一次操作只删除一位好友，保留原有聊天记录。管理台收到成功回包后会刷新名单。

### 本机接口

先启动并连接要操作的机器人。每个请求都需携带管理台页面的 `X-Helper-Token`，POST 还需使用 `Content-Type: application/json`。多机器人环境下，各请求使用同一个 `robot=<实例ID>` 查询参数。默认机器人可省略该参数。

1. 调用 `GET /api/contacts` 扫描实时通讯录。确认返回 `can_delete: true`，取响应的 `account`、`session_id`，以及 `contacts` 中目标的 `wxid`。
2. 调用 `POST /api/friend-delete`。请求示例中的账号、连接和好友 ID 需替换成扫描结果。

   ```json
   {
     "request_id": "friend-delete-demo-01",
     "session_id": "session_from_contacts",
     "account": "wxid_example_robot",
     "wxid": "wxid_example_friend",
     "keep_history": true
   }
   ```

   `request_id` 需为 16–80 个 ASCII 字母、数字、下划线或短横线。每次新操作生成一个新编号。同一编号和相同参数会返回已有结果。`keep_history` 必须为 `true`。连接变化后需重新扫描。

3. POST 返回 `request_id`、`status` 和 `error`。若仍在处理，调用 `GET /api/send-status?id=<request_id>` 查询，直到获得最终状态。多机器人环境下，查询需额外附上 `&robot=<实例ID>`。

| `status` | 含义 |
| --- | --- |
| `sending` | 已受理，等待微信回包 |
| `deleted` | 微信对该好友的删除命令返回成功，原生状态码为 `0` |
| `failed` | 微信明确拒绝，或提交后目标已经不在当前好友名单中。详情见 `error` |
| `unknown` | 超时或缺少可确认的最终回包。先在微信核对好友关系，避免重复提交 |

账号或连接变化、当前版本不支持等情况会在受理前返回 HTTP 错误，响应体含 `error`。

### 验证结果

2026 年 11 月 17 日在微信 **4.2.0.12** 上使用测试账号手动确认删除。接口最终返回 `deleted`，原生状态码为 `0`。复扫实时通讯录确认目标已移除，在微信中重新打开原会话，删除前的图片和文字仍可查看。明确拒绝、可重试回包和缺少最终回包的情况已用离线桩覆盖。

## 公众号文章

在顶部选择微信账号，进入“公众号文章”：

1. 页面自动读取当前账号在微信中已加载的关注公众号，无需逐个输入。即使还没有保存文章，也会显示为“待同步”。每个公众号显示自己的文章数和已保存正文数，可按名称、微信号或 `gh_` 标识搜索；同名公众号按独立标识区分。列表可能尚未完整加载，页面会明确提示；“刷新公众号”会重新读取关注列表及本地文章。
2. 点击“已关注”公众号即进入它的文章列表，并自动分页同步该公众号的文章。未出现在当前关注列表中的既有文章仍以“本地存档”保留，可直接查看；进入后也可点击“同步文章”主动更新。页面不会批量获取其他公众号或文章正文。
3. 列表内搜索只查找当前公众号的文章。“全部公众号”返回目录，切换公众号时清空上一篇正文和图片。自动同步失败会保留已取得内容，点击“同步文章”可重新尝试；不会循环重试。如需按标识查找，可展开“按名称手动同步”作为备用入口。
4. 点击文章即可在网页内阅读：已有正文直接显示；尚未保存的正文由程序自动请求微信加载并保存，微信可能出现阅读窗口。无需手动进入公众号历史列表或逐篇打开文章。图片随正文自动加载，失败的图片可单独重试；也可查看只读 Markdown 或导出。正文加载失败时可点击“读取正文”重试；已有正文的按钮显示为“刷新正文”。

页面底部折叠的“微信来源”仅提供出处链接，阅读文章直接使用站内正文。

读取目前只支持已核对核心与公众号浏览器指纹的微信 **4.2.0.11 / 4.2.0.12 x64**，不需要启动机器人。目录通过所选账号的登录会话主动分页获取，正文通过微信客户端自动加载，不需要用户在微信逐篇点击。公众号身份、文章链接与当前账号必须同时匹配，账号退出、重复登录或读取过程中切号时会停止本次操作。 4.2.0.12 的目录、分页与正文读取已实测，图片显示尚未单独实测。

同步按规范文章链接去重、逐页追加保存，单次最多获取 50 页、500 篇。只有微信明确返回末页时才显示列表同步完成；达到资源上限时会说明仍有历史未获取。中途失败保留已保存页面并显示进度，重新点击同步会从第一页开始。同步期间列表的文章按钮暂时禁用，避免目录和正文请求争用微信通道；当前已经打开的正文仍可阅读。切换顶部账号或管理服务断开后，不会继续请求旧账号的后续页面。获取关注列表本身不会启动机器人，也不会同步全部公众号的文章。

文章按所选账号保存在对应工作目录的 `.runtime/articles/`，与代码分开且被 Git 忽略。已保存的文章可在微信离线时阅读和导出；切换账号只显示该账号自己的文章库。图片自动排队下载并缓存在本地，同时最多下载两张，只使用正文中已校验的公开微信图片地址，不携带登录凭据。切换文章或账号会丢弃旧队列及迟到结果；管理服务连接恢复后，会继续加载尚未开始的图片。原网页中的脚本不会在管理台执行。导出的 Markdown 使用公开图片链接。

本期只提供查看和导出，不修改本地正文或公众号平台上的文章。

这些接口沿用管理台的本机访问校验和 `X-Helper-Token`，多机器人请求均加 `?robot=<实例ID>`。除连接查询外，读取库和文章操作还须显式提供当前 `account`，防止切换账号后提交旧页面请求。

| 接口 | 参数与结果 |
| --- | --- |
| `GET /api/articles-connection` | 返回当前 `account`、`connected`、`supported` 及不可用原因 |
| `GET /api/articles-publishers?account=...` | 当前账号在微信中已加载的关注公众号，返回 `publishers`（`username`、`nickname`、`alias`）、`source` 和 `complete`；不包含普通联系人或文章正文 |
| `GET /api/articles?account=...&publisher=...` | 当前账号本地文章列表，`publisher` 可选；指定公众号时只返回它的缓存，包含文章 `id` 和是否已保存正文 |
| `POST /api/articles-read` | `{"account":"...","publisher":"...","continuation":"可选"}`，同步一页目录；返回 `articles`、`has_more`、`continuation`、`page_count`、`fetched_count`、`complete_remote_history` 和 `limit_reached`，网页自动跟随后续页 |
| `POST /api/article-read` | `{"account":"...","publisher":"...","url":"..."}`，自动让微信加载该公众号的单篇正文并保存 |
| `GET /api/article?account=...&id=...` | 读取本地文章、Markdown 和图片信息 |
| `POST /api/article-media` | `{"account":"...","id":"...","index":1}`，返回已验证图片的 `mime` 和 `data_base64` |
| `POST /api/article-export` | `{"account":"...","id":"..."}`，返回 `filename` 和 `markdown` |

文章 `id` 是规范公开文章链接的 SHA256，图片序号从 1 开始。`continuation` 是绑定当前账号和同步任务的临时本地标识，微信的原始分页游标仅保存在服务端内存中。接口不返回原始客户端响应、Cookie、会话密钥或本机文件路径。读取与下载有资源上限；失败时核对所选微信仍在线后，在网页重试。

本地库每账号最多保存 5000 篇文章、合计 128 MiB；单次同步最多 500 篇。单篇 Markdown 最多 1 MiB，单张图片最多 2 MiB。图片超限时会保留正文与公开图片链接，网页提示该图片未能加载。汇总文章列表超过响应上限时，仍可从关注公众号目录进入并单独读取该公众号缓存。

## 朋友圈

“朋友圈”页面只使用正在运行且已连接的机器人。只有一个时自动选择；多个时需要在“操作账号”中选择，独立于顶部的配置账号。切换发布账号或连接后清空草稿。

页面支持文字、JPEG/PNG 图片、公开或仅自己可见的预览。框架限制正文 1000 字、最多 9 张图片，单图 5 MiB、合计 20 MiB。预览不会发布；发布须在预览里再次点击，结果未确认时不会自动重发。

当前支持微信 **4.1.15.56、4.2.0.11 和 4.2.0.12**。均已核对仅自己可见的文字和图片发布；4.1.15.56 的公开纯文字已由另一账号确认可见，4.2.0.11 和 4.2.0.12 的公开发布尚未单独实测。旧版 4.1.15.13 暂不支持朋友圈发布。

微信 **4.2.0.12** 点击“读取列表”时，会调用微信原生接口请求当前账号的朋友圈首页，并在收到完成回包后显示本次结果。无需先打开电脑微信朋友圈，页面会标注“已从微信服务器读取”。单次首页由微信决定条数，页面最多显示 20 条，以及回包中的点赞人和评论。手动读取只发送一次请求；需要新数据时再次点击，不自动翻页，也不获取完整历史，不下载或展示图片。自动评论的定期检查需在下方单独启用。

读取范围为朋友圈动态首页，个人相册读取尚未接入。本机测试中新发的仅自己可见动态只出现在手机个人相册，未包含在动态首页回包中。

2026 年 11 月 20 日在 4.2.0.12 上完成独立原生请求和管理台接口实测：服务端首页返回 10 条记录并完成字段解析，已读到另一账号刚发布且机器人可见的测试动态，同一机器人连接内连续读取成功；停止机器人后桥接正常卸载，微信保持运行。缺少页面令牌和过期连接的请求均被拒绝。账号切换、取消、失败和超时通过离线桩覆盖；请求失败时显示错误，不将旧缓存标为本次服务端结果。

微信 **4.1.15.56 和 4.2.0.11** 继续读取本机已加载的朋友圈缓存，需要先在电脑微信打开朋友圈、等待列表加载后再点击，页面标注“已读取缓存”。切换账号或连接会清除列表，读取失败时会显示错误。

每条记录下可点击“点赞”，或展开“评论”、填写内容后点击“发送评论”。使用页面上选定的操作账号，评论最多 1023 个 UTF-8 字节（约 341 个常用汉字）。已经点赞的记录显示“已点赞”。读取列表本身不会发送互动。

互动结果显示在对应记录下。同一请求编号不会重复投递；断网或超时后只查询原请求，不重新发送。微信 **4.1.15.56** 支持点赞和普通文字评论；原生评论已核对发送回执及评论列表，已点赞跳过也已实测，首次点赞发送仍待实测。**4.2.0.12 支持普通文字评论**，已实测发送并从服务端列表读回同一条评论；点赞暂未开放。4.2.0.11 的点赞和评论尚未开放；尚未提供取消赞、回复指定评论或删除评论。

### 自动评论

在朋友圈页的「自动评论」中填写固定评论，设置检查间隔，勾选启用后保存。可填写指定作者的微信 ID，每行一个；留空处理当前首页中的所有好友。设置按机器人和微信账号绑定，支持已开放评论的 4.1.15.56 与 4.2.0.12；4.2.0.12 使用服务端首页，旧版本仍受本机已加载缓存范围限制。

默认关闭，检查间隔默认 120 秒，最短 60 秒。固定评论最多 1023 个 UTF-8 字节，指定作者最多 100 个。首次启用、修改配置以及重新连接时，先读取一次列表并跳过当前记录；之后只处理新发现且发布不超过一小时的动态，跳过自己的动态、私密记录和已经由当前账号评论过的动态。每次最多评论三条，其余符合条件的记录在后续检查中继续处理，范围限于当前首页。

发送前会先将该动态标记写入当前账号的本地去重记录，重启后继续去重。结果不确定时自动暂停，不自动重发；到微信核对后可重新启用。关闭开关或停止机器人会阻止后续提交，已进入微信原生发送流程的评论仍可能完成。自动评论需要保持管理台和机器人运行；配置及去重记录保存在各机器人工作目录的 `.runtime/moments-auto/`。

微信 4.2.0.12 发现新动态后，会直接复用这次读取取得的帖子对象提交评论，评论组件不会再次读取首页。首次读取保留的对象最多 50 条、有效期五分钟；刷新列表会替换旧引用，正在评论的对象持续保留到操作结束。手动评论时若引用已过期或丢失，请重新读取列表再操作；程序不会为评论自动补拉首页。切换账号、重新连接和停止机器人会使旧引用失效。

2026 年 11 月 21 日完成对象复用链路实测：后台发现新动态后命中保留对象一次，评论期间额外首页请求为零、原生评论调用一次，服务端读回确认评论仅出现一次；引用缺失的请求在提交前失败，未补拉首页或发送评论。停止机器人后桥接正常卸载，微信保持运行。

`GET /api/moments-auto-comment` 读取设置和运行状态；`POST` 保存 `enabled`、`content`、`interval_seconds`、`authors` 和当前 `session_id`。均要求本地页面令牌，启用时核对微信连接和评论能力。

2026 年 11 月 20 日在 4.2.0.12 上使用指定测试作者、60 秒间隔完成后台定时实测：首次列表未发送评论，随后自动发现手机新发布的动态并发送设置的固定评论，服务端读回确认该评论仅出现一次。测试结束关闭监测，停止机器人后桥接正常卸载。

### 发布与升级

点击“预览”，核对账号、正文、图片和可见范围，再点击“发布”。页面等待完成回执和朋友圈编号后才显示成功；断网或超时会保留查询状态，不自动重发，结果不确定时先到手机朋友圈核对。图片上传使用微信缓存中的临时副本，原文件保持不变。

升级此功能后，需要停止机器人并关闭管理台，再重新打开 `start_web.bat`、启动机器人和刷新网页，以加载新的桥接 DLL。

## 消息监控

概览页的“消息监控”跟随顶部“当前账号”切换，约每 2 秒更新一次。每条记录显示本机记录时间、群 ID 或私聊 wxid、发送者的昵称与 wxid、消息内容。群内昵称优先使用当前群的绑定；无法识别作者时显示“未知发送者”，不会用群 ID 冒充用户 ID。

群消息还可显示发送者的群内身份，来自当前账号的群缓存，约每 15 秒检查；过期、跨连接或无法确认时不显示已确认身份。合并转发中的原作者不会继承转发者的群内身份。

文字显示完整正文（敏感密钥会隐藏）；多条长消息按传输大小分页，页面继续自动读取。图片、视频、语音、表情分别显示 `[图片]`、`[视频]`、`[语音]`、`[表情]`，文件显示文件名或 `[文件/分享]`。页面不展示媒体、不读取原始 XML、下载凭证或本机媒体路径。监控本身不触发媒体下载；图片、文件和已适配版本的视频接收按各自会话范围运行。

[合并转发](../messages/forwarded.md)会展开为多条记录，显示原作者、原消息时间、转发者和文字；图片显示类型标记及下载状态。图片下载完成后在原记录上更新，不重复新增。原作者未提供可靠 wxid 时留空，不把名称或哈希值当作微信 ID。合集内的指令不会作为现场消息执行，也不会混入当天聊天总结。

收到撤回通知后，按当前账号、会话和微信原始消息编号关联记录，保留原内容、发送者和时间并标记“已撤回”。支持群聊和私聊，合并转发的展开记录也一起标记；已保存的媒体沿用原接收目录。未捕获、已超出缓存或缺少原始编号的消息显示“原消息未捕获”，不根据相似文字猜测。标记只作用于管理台缓存，不改变微信中的撤回操作。

“插件管理”中的“本机防撤回”（`anti_recall_local`）默认关闭。开启后，当前账号的电脑微信保留原消息，其他设备正常撤回；目前仅适配微信 4.2.0.12 的指定构建。它与下方四个补发插件独立控制，可以同时使用。

默认开启的 `anti_recall` 插件提供文字和表情防撤回：文字、内置表情和 emoji 在原会话发送“撤回的消息是：原文”；已缓存的表情包直接重新发送，缓存失败时显示 `[表情]` 提示。图片、文件和已完整接收的语音分别由三个默认开启的插件补发。在“插件管理”可分别关闭，管理台标记仍保留。详细范围和升级方法见[防撤回与自动补发](../messages/recall.md)。

监控包含框架收到的消息和发送接口已接受的机器人回复，不读取微信旧历史。尚未加入支持列表或会话白名单的群，也会显示接收到的消息，便于复制群 ID；插件分发与聊天总结的记录范围仍按原配置控制。机器人发出消息的记录表示发送接口成功，不作为对方已收取的凭据。

可搜索 ID、昵称和正文。“暂停滚动”只停止自动滚动，“清空视图”只清除当前页面。每个账号在工作进程内保留最近 1000 条，首次打开显示最近 200 条，之后增量更新。停止机器人后仍可查看该次管理服务的缓存，重新加载工作进程或关闭管理服务会释放缓存，用于聊天总结的数据库独立保留。

点击「归档与导出」，可为当前账号开启「保留旧消息到本机」。默认关闭，开启时会补存当前账号的监控缓存。最早一条待写记录等待约 15 秒，或待写记录累计到 200 条时，由后台批量写入当前机器人目录的 `.runtime/chat_archive.sqlite3`。没有待写记录时不会写库。正常停止机器人、关闭管理台和下载时会提交待写记录。关闭开关会停止记录新消息，已有归档仍可导出。本地归档不会每日清理，可随消息量增长。强制结束进程时，本批尚未提交的记录可能丢失。

带微信原始消息 ID 的记录按账号、会话和消息 ID 去重，重连或重启后重新收到同一条也只保存一次。合并转发内的各条记录按序号分别保留。缺少原始消息 ID 的记录按本次捕获的编号保存。首次打开旧归档时会合并已有的重复记录，保留第一次捕获的正文和之后的撤回状态。

选择私聊或群聊以及起止日期后，即可下载 UTF-8 CSV。日期按电脑本地时间计算，包含选择的起止两天，留空表示不限。导出包含当前账号的监控缓存、开启归档后留存的记录，以及 Helper 磁盘上仍保留的群文字记录，重叠消息只导出一次。联系人备注或群聊备注可用于识别会话。图片、语音和视频以类型标记出现在 CSV 中。群文字库的保留范围取决于「记录当天文字」和「每天零点清理旧记录」设置。

消息监控和“运行日志”分别提供聊天记录与程序故障信息。群正文不因此写入原有运行日志。升级后如提示监控尚未加载，请停止机器人并重启管理台，再刷新页面。

## 配置生效与停止

插件开关、重载，以及插件编辑器中的业务函数和 JSON 选项，可在运行时保存生效。群聊、模型和发送节奏需要先停止当前机器人，等对应账号显示“未启动”后保存，再启动生效。保存前自动备份原配置到当前工作目录的 `.runtime/web/backups/`；原来的群成员资料和其他未编辑字段会保留。

API 密钥输入框留空表示保留已保存的密钥；勾选“清除已保存的密钥”才会删除。配置查询只返回“已配置”状态，不回传密钥本身。模型和语音服务是否可用仍取决于实际密钥、模型权限和网络。

大模型的“高级选项”可切换 JSON 模式、选择 `max_tokens` 或 `max_completion_tokens`，以及填写扩展参数 JSON。常规兼容接口将扩展参数留为 `{}`；官方 DeepSeek 的普通模型默认关闭思考，显式填写的思考设置优先，其他网关不会自动带入专属参数。遇到反复空正文可关闭 JSON 模式。接口地址前缀、配置示例和重试边界见[大模型配置](./configuration.md#大模型配置)。

群配置中每行一个 `@chatroom` ID。会话白名单非空时，新保存的支持群会自动加入白名单。移除支持群只停用对应群功能，不删除数据库中的称呼或聊天；如需阻止消息分发，也要从白名单中移除它。

“停止”会沿用框架的正常退出流程，先清理原生连接再卸载插件。页面显示“正在停止”时不要重复启动。若同一个项目已由另一个 `main.py` 运行，先在原终端输入 `quit`；管理台不会接管或强制结束其他实例。

关闭浏览器不会停止服务。退出管理服务时，在启动它的窗口按 Ctrl+C；机器人会同时收到正常停止请求。日志页面只显示本次管理服务启动后的最近日志，完整轮转日志仍在 `logs/bot.log`。“清空视图”只清空页面显示。

## 端口与访问范围

```powershell
python web.py --port 8877
python web.py --no-browser
```

默认端口 8765，占用时可以更换。服务固定监听 `127.0.0.1`，仅供本机浏览器使用；没有公网或局域网监听选项。页面和接口同源，管理操作验证页面会话令牌，令牌随服务重启失效，重启后刷新页面即可。

页面不调用外部字体、脚本或统计服务。账号、群配置、日志和配置备份都属于本地私有数据，继续遵循项目的 Git 忽略规则，不要上传到公开仓库。
