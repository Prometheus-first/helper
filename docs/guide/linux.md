# Linux 实验版

Linux 版正在适配中，尚不能替代 Windows 版。已接入本地网页管理台，可创建多个 Linux 微信会话并分别管理机器人。也保留受控测试命令；`main.py` 仍是 Windows 入口。

## 支持范围

## 安装与编译

请先安装对应版本的官方 Linux 微信。仓库不包含微信安装包、预编译 Linux 桥接、账号配置或测试媒体。

在项目根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdir -p native/linux/build
gcc -std=c11 -O2 -Wall -Wextra -Werror -fPIC -shared -pthread native/linux/text_bridge.c -ldl -o native/linux/build/text_bridge.so
gcc -std=c11 -O2 -Wall -Wextra -Werror -fPIC -shared -pthread native/linux/send_bridge.c -ldl -o native/linux/build/send_bridge.so
```

需要 GCC 和 Python venv 支持。生成的 `.so` 只用于本机运行，已被 Git 忽略。修改桥接后，在下次启动测试微信时加载新文件。

最小化 WSL Ubuntu 环境还需安装 `libpulse0` 和中文字体（如 `fonts-noto-cjk`）。本次 Ubuntu 26.04 环境中，缺少 `libpulse0` 会导致原版微信启动时调用空的 `pa_threaded_mainloop_new` 地址而崩溃，即使 `ldd` 没有报告缺失库。安装依赖后，微信和桥接已启动并完成扫码登录。

以下命令默认微信安装在 `/opt/wechat/wechat`。其他位置用 `--wechat /path/to/wechat` 指定；桥接也可以通过各命令的参数指定。请在图形桌面或支持图形界面的 WSL 中运行。

## 网页管理台

首次安装 Python 依赖后，在 Linux 图形桌面或 WSLg 中执行：

```bash
./start_web.sh --wechat /opt/wechat/wechat
```

脚本优先使用项目的 `.venv`，自动编译本机桥接，再启动管理服务。也可以先执行 `python -B -m tools.build_linux_bridges`，然后运行 `python -B web.py --wechat /path/to/wechat --no-browser`。端口默认 8765，可用 `--port` 修改。

1. 打开 `http://127.0.0.1:8765`，点击“登录微信”，在 Linux 微信窗口扫码并用手机确认。
2. 页面自动显示已识别的昵称和微信 ID。再次点击“登录微信”可创建另一个独立会话。
3. 勾选需要运行的账号并启动，也可以在账号行单独启动或停止。切换顶部账号选择器可查看各自配置和消息。
4. 发送图片或文件时，填写 Linux 本机的绝对路径。本地发送已在文件传输助手实测，群图片和群文件也通过了防撤回原生补发及接收端验收。
5. 发送群文字时可刷新群成员、按名字搜索并勾选艾特；也可补充该群成员的真实微信 ID，用逗号或空白分隔。勾选与手工 ID 合并去重后最多 8 人；留空则发送普通文字。不支持艾特所有人；只写正文中的 `@昵称` 不会产生真实提醒。名单未同步时仍可发普通文字，或用明确的真实成员 ID 手工艾特。

停止机器人后，微信登录窗口保持运行。使用账号行的“退出微信”关闭该会话。每个微信进程使用独立 HOME 和缓存，机器人配置、群备注、插件覆盖及聊天数据按账号保存在 `.runtime/linux/accounts/`。之前单账号配置仍位于 `.runtime/linux/`，不会自动复制到其他账号。

单账号自动读取、机器人启停和文本收发已实机验证；跨账号隔离已通过模拟测试，真实的双账号同时登录和收发还需要实机验证。尚未适配的功能在网页中隐藏或标记为不可用。

“联系人”页面支持扫描当前机器人账号的好友，按昵称、备注、微信 ID 和标签搜索，并查看好友资料。扫描只读取微信已同步到本机的联系人；离线或未同步的数据可能不完整。读取时临时使用当前微信进程中的数据库密钥，密钥和解密后的数据库不会写入文件或日志。运行用户需要有读取该受管微信进程内存的权限。Linux 微信账号变更、进程退出或文件指纹不匹配时，读取会终止。

群成员只读当前登录账号的本地群数据。每次查询使用新事务，要求扩展名单与 `chatroom_member` 索引的成员集合一致、没有重复且含机器人自己；缺失或不完整返回“未就绪”，不会当作空群。首次查询准备只读数据库连接，之后复用连接但不缓存成员结果；账号、进程或数据库变更后立即弃用。群主取自独立字段；管理员按已验证并与手机名单核对的成员权限位识别，缺失或异常字段保持未知，不按名字或排列顺序猜测。

运行期间约每 15 秒检查已配置或已发现的群（仍受收发白名单限制）。初始快照只建立基线，成员变化至少连续两次完整快照确认，读取失败会中断确认；已验证的系统通知只有得到当前完整名单佐证才提前发布。系统通知和名单差分去重，重启不补发历史入群事件。消息监控显示“成员入群/成员退群”摘要，不保存原始系统 XML。`group_notice` 插件现在可用，默认关闭；启用后按其配置发送欢迎和离群提示。被移出沿用 `leave` 事件，不另行推测离群原因。

### 定时任务

在管理台选择已登录的账号，进入“定时任务”，可创建按分钟间隔或每天指定时间运行的任务；内置动作支持发文字，插件可声明其他动作。任务按当前账号隔离，配置的白名单继续生效。时间使用运行 Linux 管理台的系统时区，管理台或机器人离线期间错过的任务不会补发。Linux 版本已完成模拟网页和账号隔离验证，真实微信定时发送仍待实测。

### 防撤回

Linux 管理台现已接入 `anti_recall`、`anti_recall_image`、`anti_recall_file` 和 `anti_recall_voice`，可在插件管理分别开关。文字、动态表情、群图片和群文件均已实机恢复成功并通过接收端验收；文件发送保留独立快照直到微信进程退出，并支持微信重名缓存格式。语音发送已用 1 秒测试音确认可播放，完整入站音频的数据库补充读取已完成，新群短语音自动缓存、撤回后单次补发与接收端原声播放均通过实机验收。媒体的可恢复范围取决于完整原件是否已进入本轮缓存。功能的通用规则见[防撤回与自动补发](../messages/recall.md)，实现与验证边界见[Linux 防撤回](https://github.com/Prometheus-first/helper/blob/linux/native/linux/RECALL.md)及 [Linux 语音](https://github.com/Prometheus-first/helper/blob/linux/native/linux/VOICE.md)。

语音防撤回只补发缓存原音频，不做语音识别。Linux 已开放完整原音频的通用 `voice.receive`，此能力不包含 ASR；`voice_reply` 使用文字输入、已配置的模型回复及 TTS 生成语音，仍需单独配置模型、TTS 服务和群音色，不能据此自动听懂收到的语音。本轮仅实测 1 秒测试音和约 2–5 秒群短语音；私聊仅离线验证，60 秒/256 KiB 极限和付费 TTS 在线链路未实测。

文字缓存沿用每条 2000 字符的上限，超过部分不能保证恢复。媒体缓存按账号和机器人连接隔离，最多 128 个文件、合计 256 MiB；图片每张最多 20 MiB，文件预算最多 256 MiB，但默认每次扫描只读取 64 MiB，不能据此宣称可恢复任意 256 MiB 附件。只处理原消息明确指定且通过完整 MD5 校验的媒体；缺少完整缓存、校验失败、缓存被淘汰或机器人已重启时不能恢复。

图片自动下载在接收前绑定当前账号和会话范围：收发白名单为空时，覆盖该账号的普通好友及群会话；非空时只处理最多 64 个允许的会话。文件传输助手、公众号和系统会话不纳入自动下载。下载请求带连接代次，旧连接不能沿用新连接的范围。图片和文件缓存有限并发处理，撤回通知先到时会等待缓存结果。白名单为空的群图片快速撤回已实机确认缓存及补发；但撤回过快、下载未完成或原消息未被捕获时，仍可能无法恢复。文件只使用微信已经落盘的附件，不主动下载缺失文件。

更新桥接后须停止机器人、退出对应微信，再重新启动并登录，使进程加载新的 `.so`。仅重载插件不能升级已经加载的原生桥接。启动机器人并开启相应插件后再接收测试消息；历史消息和此前连接的缓存不补发。


### 无桌面服务器

安装 `xvfb`、`xauth` 和 `ffmpeg`，并安装本项目 Python 依赖后，启动管理台。若需自动从已识别的快捷登录页面切换到扫码页面，还需 `xwininfo` 和 XTest 运行库（通常来自 `x11-utils`、`libxtst6`）：

```bash
./start_web.sh --wechat /opt/wechat/wechat --headless --no-browser
```

通过 SSH 转发本机端口后，在浏览器打开 `http://127.0.0.1:8765`：

```bash
ssh -L 8765:127.0.0.1:8765 user@server
```

点击“登录微信”，等待页面显示二维码并扫码。每个微信会话使用独立的虚拟显示和认证文件，登录成功后页面清除二维码。`GET /api/linux-login-qr?robot=会话ID` 返回该会话的状态和 PNG Base64，需带页面会话令牌；它只用于已由管理台启动的微信。虚拟显示属于管理台进程，停止会话时一并关闭。自动切换只针对已识别的快捷登录页面；其他页面不会被自动点击。二维码长时间加载时，请检查 Linux 系统能否访问微信服务。

## 受控验证入口

每个命令会启动一个加载桥接的 Linux 微信。先退出已运行的同一 Linux 微信，运行命令后扫码登录。停止测试会停用桥接采集和发送接口，微信保持打开；后续重新加载桥接时才需要退出并重新启动。

### 文件传输助手发文字

```bash
python -B -m tools.linux_text_send_test
```

登录后在终端输入 `send` 发送 `WX_LINUX_NATIVE_SEND_01`；输入 `quit` 停用接口。启动命令本身不会自动发消息。

### 私聊和群聊文本回复

```bash
python -B -m tools.linux_text_roundtrip_test --timeout 1800
```

桥接就绪后，用另一个测试账号：

1. 私聊发送 `WX_LINUX_BRIDGE_07_SEND`，预期回复 `WX_LINUX_FRIEND_REPLY_01`。
2. 在测试群发送 `WX_LINUX_BRIDGE_08_SEND`，预期在同一群回复 `WX_LINUX_GROUP_REPLY_01`。

每类只回复一次，其他文字不会触发回复。会话范围来自本轮收到的测试消息，不需要填写个人 wxid 或群 ID。

### 后台收到图片后自动下载

```bash
python -B -m tools.linux_media_test --auto-download-images --timeout 1800
```

登录后让电脑微信停留在文件传输助手。用另一个测试账号先私聊发送 `WX_LINUX_MEDIA_ARM_11`，再发一张全新图片；电脑端不要进入私聊或点开图片。

工具只处理该测试账号的一张图片：保留原生消息上下文，在微信协程中下载原图，读取当前账号缓存并解密 V2 格式，完整 MD5 校验通过后再回发到文件传输助手。已通过后台实机验证，手机确认回发图片内容一致。

此入口仍是验证工具，不会接管所有会话的日常媒体收发。临时图片写入当前用户的私有临时目录；该验证工具不将原始 XML、CDN 凭据或缓存密钥写入测试输出。管理台的 `.runtime/` 可能包含账号信息、配置和聊天数据，属于本地私有数据，不应提交到仓库。

### 附件后台落盘与语音识别

```bash
python -B -m tools.linux_media_test --receive-voice --watch-files --file-name WX_LINUX_FILE_RECV_02.txt --timeout 1800
```

附件由微信后台落盘后可校验并回发。该受控工具已验证语音元数据及上下文识别；产品侧原生语音发送另已确认可播放，群短语音完整入站缓存与防撤回已通过真实 SessionLease 链路和接收端播放验收。

## 开发接口

- `LinuxNativeTextBackend` 是实验性文本后端，复用框架消息转换、插件分发和回复链路。发送需要显式提供 `send_bridge_path`，通过 `send_targets` 允许指定会话；默认仅文件传输助手。
- `LinuxNativeSender` 提供 `send_text()`、`send_at_text()`、`send_image()`、`send_file()`、`send_emoticon()`、`send_voice()`，以及受控的图片范围绑定、上下文查询与下载接口。表情发送需桥接报告 `local_emoticons`，语音发送需报告 `local_voice`，管理台才开放相应能力。
- 群艾特复用 `ctx.reply_at(message, text)` 和 `ctx.send_at_text(room, text, members)`，声明 `group.text.mention` 能力；长文本由框架按 1023 个 UTF-8 字节分段，仅第一段携带艾特名单。原生名单与可见标签分别传入，不依赖昵称反查。艾特对话、成语接龙等插件现可通过该能力检查，仍需自行配置并启用。
- `LinuxImageDownloader` 保留受控好友图片验证入口；管理台防撤回使用独立 `LinuxMediaReceiver`，在本连接内发布 `pending` / `ready` / `failed` 状态。原生群图片下载、完整校验与撤回补发已实机通过。
- Linux 声明 `image.receive`、`file.receive`、`voice.receive` 及对应好友/群作用域；完整 ready 缓存投递普通插件一次，未完成和失败状态仅供监控与防撤回。专用 `image.recall.receive`、`file.recall.receive`、`voice.recall.receive` 继续可用。报告 `local_voice` 的桥接另开放 `voice.send`、`friend.voice.send`、`group.voice.send`。Windows 后端保留原能力并提供专用别名。
- `ctx.contacts()` 返回当前账号已同步的好友资料、备注和标签；`ctx.contact_labels()` 单独读取已加载的标签缓存。插件需分别声明 `contact.read` 或 `contact.labels.read`，结果的 `complete` 为 `false`，不能视为服务端完整名单。
- `ctx.group_members(room)` 复用现有群成员接口，能力为 `group.members.read`；返回标准成员元组或 `None`，后者表示无法提供完整快照。`group.events` 使用现有 `message.data['group_event']` 的 `join` / `leave` 结构，账号和连接隔离规则与 Windows 相同。
- 原生图片上下文最多缓存 16 条。好友验证入口绑定测试双方账号；管理台按当前账号和收发白名单绑定范围（白名单为空时使用普通好友和群会话），绑定、查询及下载核对 `scope_generation`。未知版本、账号或代次不匹配、未完成下载或校验失败都会拒绝返回图片。
- 下载或发送等待超时后，迟到回调结束会允许后续请求继续执行；原请求仍保持结果未知，不会自动重发。
- 本地通道核对 PID 和 UID。原生调用在微信自己的协程中执行；超时或连接中断时报告结果未知，不自动重试，避免重复发送。
- Linux 进程锁使用 `flock`，Windows 仍使用 `msvcrt`。共用运行时新增的能力列表参数可选，Windows 默认行为保留。

## 离线检查

```bash
python -B -m unittest discover -s tests -p 'test_linux_*.py'
```

包含可重复编译的合成 fixture，覆盖文本与媒体协议、群艾特名单及长文本分段、撤回匹配、联系人解析、账号隔离、断线去重、进程身份、原生调度、图片上下文范围、缓存解密、MD5 和路径检查。测试不会连接真实微信、调用模型或读取个人聊天记录。

发布前还应运行 `python -B -m unittest tests.test_publication_checks`，并对实际待发布目录执行 `tools.check_publication.inspect()`。检查目标是源码和示例配置；本地 `.runtime/`、日志、`.so`、崩溃转储和测试媒体不得进入提交。

## 测试结束与隐私清理

先停止机器人并退出本次受管微信，再关闭管理台服务，确认对应进程结束。然后清理项目 `.runtime/`：其中包含受管微信 HOME、登录状态、账号配置、联系人与聊天数据库、收发媒体缓存、日志和测试探针。删除这些数据会让下次启动回到首次登录和配置状态。

若测试曾直接启动独立 Linux 微信，还需清理该测试用户的 `~/xwechat_files/` 与 `~/.xwechat/`。仅处理已经确认属于本次测试的目录；其他日常微信安装及数据目录不在项目清理范围内。另行删除本次测试截图、安装包缓存、反汇编临时输出，以及已退出进程留下的 `helper-*` 私有临时目录。

`native/linux/build/` 是可重建的本地桥接产物，可以删除；保留源码、合成测试 fixture、依赖环境和示例配置。发布时从 Git 待提交文件导出独立目录，检查真实账号/群标记、密钥、个人路径及运行产物，再提交和推送。忽略规则只防止误提交，不能替代本机隐私数据清理。

通用媒体事件字段、缓存生命周期与表情导出说明见 [Linux 通用媒体与表情导出](https://github.com/Prometheus-first/helper/blob/linux/native/linux/MEDIA.md)。
