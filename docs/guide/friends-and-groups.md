# 好友申请与群管理

这些功能使用当前绑定的机器人账号。群管理仅接受程序控制台命令，不读取群聊或文件传输助手里的管理指令。

## 查看和通过好友申请

启动 `python main.py` 后，在程序控制台输入：

```text
friend-requests
accept-friend fr_控制台显示的申请ID
```

好友申请通过独立的类型 `37` 事件接收。终端会显示申请 ID、对方微信 ID（如果申请提供）及昵称；申请票据、原始 XML 不写日志。`friend-requests` 可查看本次连接收到的申请和状态，不补抓程序启动前的申请历史。

申请凭据只保留在当前账号、当前连接的内存目录中，默认保留一小时，最多 512 条。该时间是框架的内存保留策略，不代表微信票据的有效期。退出、断线或重新连接后需要对方重新发起申请。

## 自动通过

`friend_auto_accept` 插件默认关闭，旧配置未添加这个插件时同样保持关闭。在控制台明确启用：

```text
enable friend_auto_accept
```

关闭：

```text
disable friend_auto_accept
```

启用状态会保存在本地配置。可在 `bot_config.json` 设置验证文字关键词：

```json
{
  "plugins": {
    "friend_auto_accept": {
      "enabled": true,
      "verification_keywords": ["约定的验证词"]
    }
  }
}
```

关键词列表为空时，通过所有当前支持的实时入站好友申请；非空时，验证文字包含任意一个关键词才自动通过。不匹配的申请仍可在控制台手动处理。修改关键词后执行 `reload friend_auto_accept`。

类型 `37` 还包含验证结果等通知；当前仅将明确 `opcode=2` 的入站申请列为待处理，不会对结果通知重复操作。相同申请已处理后不会自动重试，失败可让对方重新发起申请。

## 邀请好友进入已有群

```text
invite-members 12345678@chatroom wxid_example_friend
invite-members 12345678@chatroom wxid_example_first wxid_example_second
```

每次邀请 1–8 位已添加的好友，机器人账号需在目标群中。接口走微信原生邀请流程，受微信权限、群设置及成员状态约束。操作成功表示邀请请求成功，不表示对方已经确认入群。

## 创建群聊

```text
create-group wxid_example_first wxid_example_second
```

每次提供 2–8 位已添加的好友，机器人自身不必放入名单。成功后控制台显示服务器返回的新群 ID；框架不会根据最近聊天猜测新群。人数范围是当前框架接口限制，不是微信的群人数上限。

参数需要真实微信 ID，不能使用昵称或备注代替。同一操作不能包含重复 ID、群 ID、系统账号或机器人自己。失败、超时或账号变化时不自动重试；可先在微信中核对操作结果。

## 进群欢迎、退群提醒和群友昵称

在程序控制台开启或关闭插件：

```text
enable group_notice
disable group_notice
```

插件默认关闭。开启后，在已监控的群中，新人加入时回复「欢迎 昵称 加入群聊！」，成员离开时回复「昵称 离开了群聊。」。本群 `/绑定` 的名字优先，其次使用实际群昵称，未设置群昵称时使用微信名。不同群的昵称分开保存。

群名单每 15 秒检查一次，连续两次确认变化才触发通知；微信缓存更新后通常再等待 15–30 秒。受支持的、携带明确成员 ID 的群系统事件，在完整实时名单也支持相同变化时可以提前通知；历史提示、普通聊天、仅有人名的提示不会直接触发通知。第一次读取名单、重新连接只建立基线，不会给所有老成员发欢迎，也不补发离线期间的变化。读取失败、名单为空或缺少机器人本身时不推断退群。

监控范围为会话白名单内的已配置群和当前连接发现的群。白名单为空时不限制会话；此前从未接收过消息、也未写入成员配置的群，需要先在群里发一条消息以被发现。仅记录 ID 的群消息日志继续保持原有行为。

可在 `bot_config.json` 的 `plugins` 中配置文案，再输入 `reload group_notice`：

```json
{
  "group_notice": {
    "enabled": true,
    "welcome": true,
    "leave_notice": true,
    "welcome_template": "欢迎 {nickname} 加入群聊！",
    "leave_template": "{nickname} 离开了群聊。"
  }
}
```

两个开关可以独立控制。模板只允许 `{nickname}` 占位符，不需要配置大模型。

查询当前名单和昵称同样在控制台操作：

```text
group-members 12345678@chatroom
group-nickname 12345678@chatroom wxid_example_friend
```

只读取当前绑定账号的微信缓存，不主动请求服务器刷新；微信未同步名单时提醒可能延迟。缓存未就绪时返回不可用，不把残缺名单当成完整群成员表。可在微信中打开目标群的成员列表后重试。`members 群ID` 仍然查询框架的绑定目录，两者用途不同。

## 验证范围

底层锁定 Windows x64 微信 4.1.15.13。群邀请、创建本轮只做代码、本地 ABI 和模拟调用检查，尚未执行真实邀请或创建群聊。

2026-10-19 已实测自动通过好友申请：从独立好友验证通道接收实时申请，原生服务返回通过成功，对方确认可以正常聊天；测试结束后桥接 DLL 正常卸载。启动前已有的申请不会因打开“新的朋友”页面被自动通过。

2026-10-20 已实测群成员与昵称查询，以及同一测试账号退出、重新入群：完整缓存名单自动更新，两次变化各触发一条对应提醒，已确认退群提醒和进群欢迎均送达。测试程序退出后桥接 DLL 正常卸载。不同群及其他服务器同步场景的时效仍取决于微信缓存更新。
